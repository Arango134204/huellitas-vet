REQUISITOS PREVIOS
------------------
1. Node.js instalado (versión 20 o superior). Compruebe con:
      node -v
      npm -v

2. MongoDB instalado y CORRIENDO en local (puerto 27017).
   En Windows puede verificar el servicio "MongoDB" en services.msc
   o ejecutar en PowerShell:
      Get-Service *mongo*

3. Un navegador (Chrome o Edge) y, opcionalmente, Postman.


--------------------------------------------------------------------------------
PASO 1. ABRIR EL PROYECTO
--------------------------------------------------------------------------------
Abra la carpeta del proyecto en VS Code / Cursor:

  C:\Users\User\Desktop\UAM\DESARROLLO WEB II\huellitas-vet

La estructura importante es:
  Backend\        -> API (Node + Express + MongoDB)
  web-angular\    -> Panel de administración (Angular)
  documentacion\  -> Documentos, Postman e instrucciones


--------------------------------------------------------------------------------
PASO 2. CONFIGURAR Y ENCENDER LA API (Backend)
--------------------------------------------------------------------------------
Abra una terminal (Ctrl + ñ en VS Code) y ejecute:

  cd Backend
  npm install

Si no existe el archivo .env, créelo a partir del ejemplo:

  copy .env.example .env

El contenido de .env debe ser:

  PORT=3900
  MONGODB_URI=mongodb://127.0.0.1:27017/huellitas-vet

Cargue los datos de prueba (3 dueños, 4 mascotas, 4 citas):

  npm run seed

Arranque el servidor:

  npm start

Debe aparecer algo como:

  Conexión a MongoDB establecida (mongodb://127.0.0.1:27017/huellitas-vet)
  Servidor corriendo en http://localhost:3900

Compruebe en el navegador o Postman:

  GET http://localhost:3900/
  Respuesta esperada: {"message":"Servidor OK", ...}

DEJE ESTA TERMINAL ABIERTA. Si la cierra, la API se apaga.


--------------------------------------------------------------------------------
PASO 3. ENCENDER EL PANEL ANGULAR (Frontend)
--------------------------------------------------------------------------------
Abra UNA SEGUNDA terminal y ejecute:

  cd web-angular
  npm install
  npm start

Cuando termine de compilar, abra:

  http://localhost:4200

Ahí verá el panel: Inicio, Dueños, Mascotas y Citas.


--------------------------------------------------------------------------------
PASO 4. DEMOSTRACIÓN RÁPIDA EN EL PANEL (Angular)
--------------------------------------------------------------------------------
1. En http://localhost:4200 ver el resumen y las citas de hoy.
2. Ir a Dueños: registrar uno nuevo, buscar por nombre.
3. Ir a Mascotas: registrar una mascota ligada a un dueño.
4. Entrar a Detalle de una mascota y subir una foto (PNG/JPG).
5. Ir a Citas: agendar una cita con fecha FUTURA.
6. Pulsar "Atender" o "Cancelar" en una cita pendiente.


--------------------------------------------------------------------------------
PASO 5. PRUEBAS CON POSTMAN
--------------------------------------------------------------------------------
IMPORTANTE: La API debe estar corriendo (npm start en Backend) antes de probar.

A) Importar la colección (recomendado)
--------------------------------------
1. Abra Postman.
2. File → Import (o Import en la barra superior).
3. Seleccione el archivo:
     documentacion\HuellitasVet.postman_collection.json
4. En la colección verá carpetas: Servidor, Dueños, Mascotas, Citas.
5. Variables de la colección (edítelas cuando cree registros):
     baseUrl    = http://localhost:3900
     duenoId    = (pegar el _id al crear un dueño)
     mascotaId  = (pegar el _id al crear una mascota)
     citaId     = (pegar el _id al crear/agendar una cita)

B) Cómo enviar JSON en Postman
------------------------------
Para POST, PUT y PATCH:
  - Body → raw → JSON  (selector a la derecha)
  - Header Content-Type: application/json (Postman lo pone solo con raw JSON)

Para subir imagen:
  - Body → form-data
  - Key: imagen   |  Type: File  |  Value: elija un .png o .jpg


C) Pruebas paso a paso (sígalas en orden)
-----------------------------------------

----- PRUEBA 1. Servidor activo -----
Método:  GET
URL:     http://localhost:3900/
Body:    (ninguno)
Esperado: 200
  {"message":"Servidor OK","proyecto":"HuellitasVet API",...}


----- PRUEBA 2. Listar dueños -----
Método:  GET
URL:     http://localhost:3900/api/duenos
Esperado: 200 → status:"success", total:3 (si corrió npm run seed)


----- PRUEBA 3. Buscar dueño por nombre -----
Método:  GET
URL:     http://localhost:3900/api/duenos?buscar=laura
Esperado: 200 → solo aparece Laura Gómez


----- PRUEBA 4. Crear dueño válido -----
Método:  POST
URL:     http://localhost:3900/api/dueno/save
Body (raw → JSON):
{
  "nombre": "Pedro Pérez",
  "documento": "1088999888",
  "telefono": "3101234567",
  "email": "pedro@mail.com",
  "direccion": "Centro, Pereira"
}
Esperado: 201 → status:"success" y el dueño con su _id
ACCIÓN: copie el _id y péguelo en la variable duenoId de Postman
        (o úselo en las siguientes URLs donde diga ID_DUEÑO)


----- PRUEBA 5. Crear dueño con datos inválidos -----
Método:  POST
URL:     http://localhost:3900/api/dueno/save
Body:
{
  "nombre": "Lu",
  "documento": "123",
  "telefono": "12",
  "email": "malo"
}
Esperado: 400 → "Datos no válidos" + lista de errores
  (nombre corto, teléfono inválido, email inválido)


----- PRUEBA 6. Documento duplicado -----
Método:  POST
URL:     http://localhost:3900/api/dueno/save
Body:    el mismo de la Prueba 4 (documento 1088999888)
Esperado: 409 → "Ya existe un registro con ese documento"


----- PRUEBA 7. Listar mascotas -----
Método:  GET
URL:     http://localhost:3900/api/mascotas
Esperado: 200 → mascotas con nombre del dueño (populate)


----- PRUEBA 8. Filtrar mascotas por especie -----
Método:  GET
URL:     http://localhost:3900/api/mascotas?especie=perro
Esperado: 200 → solo perros (Rocky, Toby, …)


----- PRUEBA 9. Crear mascota válida -----
Método:  POST
URL:     http://localhost:3900/api/mascota/save
Body:
{
  "nombre": "Luna",
  "especie": "gato",
  "raza": "Siamés",
  "peso": 3.5,
  "dueno": "ID_DUEÑO"
}
(Reemplace ID_DUEÑO por el _id de la Prueba 4)
Esperado: 201 → mascota creada
ACCIÓN: copie el _id → variable mascotaId


----- PRUEBA 10. Crear mascota inválida -----
Método:  POST
URL:     http://localhost:3900/api/mascota/save
Body:
{
  "nombre": "",
  "especie": "dragon",
  "peso": -2,
  "dueno": "ID_DUEÑO"
}
Esperado: 400 → errores de nombre, especie y peso


----- PRUEBA 11. Ver mascota con historial -----
Método:  GET
URL:     http://localhost:3900/api/mascota/ID_MASCOTA
Esperado: 200 → mascota + historial (array de citas)


----- PRUEBA 12. Subir imagen (Multer) -----
Método:  POST
URL:     http://localhost:3900/api/mascota/upload-image/ID_MASCOTA
Body:    form-data
  Key = imagen   (tipo File)   Value = un archivo .png o .jpg pequeño
Esperado: 200 → mascota.imagen con el nombre del archivo
Comprobar: GET http://localhost:3900/api/mascota/imagen/NOMBRE_ARCHIVO
           (debe devolver la imagen)


----- PRUEBA 13. Id con formato incorrecto -----
Método:  GET
URL:     http://localhost:3900/api/mascota/123
Esperado: 400 → "El id enviado no es válido"


----- PRUEBA 14. Resumen de citas -----
Método:  GET
URL:     http://localhost:3900/api/citas/resumen
Esperado: 200 → totales por estado (pendiente, atendida, cancelada) y citasHoy


----- PRUEBA 15. Listar citas pendientes -----
Método:  GET
URL:     http://localhost:3900/api/citas?estado=pendiente
Esperado: 200 → solo citas pendientes, con mascota y dueño


----- PRUEBA 16. Agendar cita válida -----
Método:  POST
URL:     http://localhost:3900/api/cita/save
Body:    (use una fecha FUTURA; cambie la fecha si hace falta)
{
  "mascota": "ID_MASCOTA",
  "fecha": "2026-12-15T10:00:00",
  "motivo": "Control general",
  "veterinario": "Dra. Salazar",
  "origen": "web"
}
Esperado: 201 → cita con estado "pendiente"
ACCIÓN: copie el _id → variable citaId


----- PRUEBA 17. Regla: cita en el pasado (debe fallar) -----
Método:  POST
URL:     http://localhost:3900/api/cita/save
Body:
{
  "mascota": "ID_MASCOTA",
  "fecha": "2020-01-01T10:00:00",
  "motivo": "Prueba pasado",
  "veterinario": "Dra. Salazar"
}
Esperado: 400 → "No se puede agendar una cita en el pasado"


----- PRUEBA 18. Regla: solape del mismo veterinario (debe fallar) -----
Método:  POST
URL:     http://localhost:3900/api/cita/save
Body:    misma fecha/hora (±30 min) y mismo veterinario de la Prueba 16
{
  "mascota": "ID_MASCOTA",
  "fecha": "2026-12-15T10:15:00",
  "motivo": "Otra cita",
  "veterinario": "Dra. Salazar"
}
Esperado: 409 → mensaje de choque / franja ocupada


----- PRUEBA 19. Marcar cita como atendida -----
Método:  PATCH
URL:     http://localhost:3900/api/cita/ID_CITA/estado
Body:
{
  "estado": "atendida",
  "observaciones": "Paciente estable"
}
Esperado: 200 → estado "atendida"


----- PRUEBA 20. Transición inválida (debe fallar) -----
Método:  PATCH
URL:     http://localhost:3900/api/cita/ID_CITA/estado
Body:
{
  "estado": "pendiente"
}
Esperado: 409 → "Transición no permitida: de «atendida» a «pendiente»"


----- PRUEBA 21. No borrar dueño con mascotas (debe fallar) -----
Método:  DELETE
URL:     http://localhost:3900/api/dueno/ID_DUEÑO
Esperado: 409 → no se puede eliminar porque tiene mascotas activas


----- PRUEBA 22. Ruta inexistente -----
Método:  GET
URL:     http://localhost:3900/api/ruta-que-no-existe
Esperado: 404 → "Ruta no encontrada"


D) Qué mostrarle a la profesora en Postman
------------------------------------------

--------------------------------------------------------------------------------
PROBLEMAS FRECUENTES
--------------------------------------------------------------------------------
- "Error al conectar con MongoDB"
  -> MongoDB no está iniciado. Arranque el servicio MongoDB.

- El panel dice "No se pudo conectar con la API"
  -> La API no está corriendo en el puerto 3900. Revise la Terminal 1.

- Puerto 3900 o 4200 ocupado
  -> Cierre el proceso anterior (Ctrl+C) o reinicie el equipo.

- npm install falla
  -> Verifique conexión a internet y que Node esté instalado.

- La foto no sube
  -> Use PNG, JPG, JPEG, GIF o WEBP de máximo 2 MB.
  -> El campo del formulario debe llamarse "imagen".
